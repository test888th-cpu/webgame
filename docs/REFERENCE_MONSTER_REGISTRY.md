**Status:** data only, validated, not used by gameplay. **Reference:** World of
ClaudeCraft `d2b91e0884cb269422c28d0b42d2a30a01de130a`.

**Files:**

- `data/registry/reference_monsters.json`, generated by
  `tools/content/build_reference_registries.py` (see
  [REFERENCE_REGISTRY_BUILDER.md](REFERENCE_REGISTRY_BUILDER.md)).
- The accessor is `client/sim/RpgMonsterRegistry.gd`, loaded through
  `client/sim/RpgRegistryLoader.gd`.

**How it was counted.** The tables are evaluated, not matched as text
(`tools/content/ts_eval.py`, which never runs the reference's code), so templates
built by a helper are included.

by the builder: `{ id: '<literal>' }` objects with `hpBase` at their top level. It
still finds exactly 316: 302 in `MOBS` and 14 in the Studio overlay. The full,
generated reconciliation is `count_reconciliation` in `reference_monsters.json`.

**Corrections:**

- **Missing records.** The earlier report said "53 missing". That figure left out
  the 9 Tideglass Reflections; the correct number is 62 in `MOBS`.

  monsters. They are in the Studio overlay, and are labelled with that table.
- **Parsing, not duplicates.** No id appears in both tables, and no record the text
  match found is unregistered. The whole difference comes from parser coverage, not
  from duplicate handling or new entity types.

## 3. Validation results (this phase)

**UNKNOWN mechanics: 68 → 0.**

- The earlier text parse left 68 nested mechanic values UNKNOWN, among them
  `trashKit`, `rankMechanics`, `petRanged`, `breathCone`, `deathThroes` and
  `broodWhelp`. All are now resolved, including shared constants such as
  `BRINE_MEND_KIT` and cast ids defined in other modules.
- Every field of every record is a declared `MobTemplate` field
  (`fields_not_in_mob_template` is empty).
- The full list is in [REFERENCE_UNKNOWN_REPORT.md](REFERENCE_UNKNOWN_REPORT.md).

**Classification semantics.**

- The reference has **no mini-boss flag**.
- `rare` is its rare-spawn flag: 26 records, among them Karesh the Parched and the
  rare world spawns.
- **No mini-boss.** The earlier registry exposed `role() == "mini_boss"` for rares,
  and an interim `proposed_role: mini_boss` replaced it.
  - The owner rejected any rare → mini-boss mapping (decision F2, 2026-11-17).
  - Both are removed: the registry, `RpgMonsterRegistry` and the matrix use only the
    source classification, and the matrix slot is `rare`.
  - A test checks that `mini_boss` appears nowhere in the registry.

## 4. The Studio (custom-map) overlay

The 15 `STUDIO_CONTENT.mobs` records are kept apart from the base world:

- `registry_table: "STUDIO_CONTENT.mobs"`.
- **The 14 Scorching Wastes templates** are EXCLUDED (owner decision).
- **`objective_practice_champion`** is NOT_AN_ENEMY: an authored map's objective
  rehearsal body.
- **None is a matrix candidate.** The reference merges them only while an authored map
  is active (`studio_content.ts` `addMissing`), never into the base world's `MOBS`.

## 5. Namespaces and collisions

- **Addressing.**
  - A reference record is `reference:<id>`.
  - One of The Iron Legacy's own records is `iron_legacy:<id>`.
- **Lookups.**
  - `RpgRegistryLoader.reference_record()` accepts only `reference:` ids.
  - `RpgRegistryLoader.game_record()` accepts only `iron_legacy:` ids.
  - A bare id is refused by both.
- **The audit** is `data/registry/id_collisions.json`, compared with the live data
  by `test_rpg_registry_loader.gd`.
  - **Monsters:** one shared bare id, `training_dummy`. The game's own record is a
    120 HP practice dummy; the reference's is a 999,999 base HP practice target
    (NOT_AN_ENEMY). Each keeps its own record.
  - **Items:** no shared ids.
  - **Across domains:** no reference monster id is also a reference item id.
  - **Loot tables:** all ids are unique.

## 6. Loading architecture

- **`ContentDB.gd`** keeps only the reviewed file reader (`read_registry`, and `_read`
  for `client/data`). It holds the loaded `rpg` rule registries, and is 996 lines.
- **`RpgRegistryLoader.gd`** does the rest:
  - lists the registries;
  - loads them through the reader it is given;
  - validates them and owns the namespaces.

  It does no file access itself, so the purity guard (`test_sim_purity.gd`) is
  unchanged.
- **`RpgMonsterRegistry.gd`** and **`RpgLootRegistry.gd`** are pure, read-only
  accessors.
